DSTerafoods Design System

A neutral, professional base with a customizable accent chosen per outlet. The base palette never changes; the accent is one of six the owner picks. One identical system that feels appropriate across four tiers — a juice-bar counter to a multi-outlet group. Tuned for budget Android (Helio G35 / 720p / sunlight / one thumb), bilingual EN / বাংলা, ৳ currency.

Hue-lane discipline. Saffron/clay accents are warm cousins of warning/urgent. They never collide because signals only ever appear with their soft background + an icon/word, and the accent never appears as a status tag. Warning lives in a mustard lane (#946A0F), urgent in vivid orange (#DC4A18), danger in true red (#BC3A2B) — three separated hues.

d · Data-viz — categorical, lower-chroma so it reads as "data," not "brand"

viz-1 #4C6FA5 viz-2 #C28A3D viz-3 #8A6FA0 viz-4 #6F9B6A viz-5 #54827E

Distinguishable when adjacent; deliberately desaturated. The accent is never used as a chart series, so chart colors stay self-contained regardless of which accent is active.

e · Color usage rules — enforceable

✓ Accent appears ONLY on: CTAs / primary buttons, the FAB, selected states, focus rings, and accent-soft / accent-wash tinted surfaces.
✗ Accent never signals status. It cannot mean warning, error, or a negative/positive delta.
✓ Negative deltas always use danger; positive deltas always use success — never the accent, regardless of outlet.
✗ Signal colors never used as decoration. urgent only when a late value > 0; a count of 0 uses muted, not a green "0".
✓ Zero-state vs no-data: a real 0 renders in ink (it's a fact). No data yet renders the label in muted-soft with an em-dash "—" — never a colored signal.
✗ Never paint a full surface in accent at full strength behind body text (accentInk is for short labels/buttons, not paragraphs).

02Typography

Two families, two weights. Hierarchy comes from size, color, and tabular numerics — not from many weights, which muddy on low-DPI screens in sunlight.

a · Families

RoleFamilyWhy
EN UI / bodyRoboto (system)Shipped with Android — zero font payload, perfectly hinted for low-DPI, has true tabular figures. The performance-correct choice over a webfont on Helio G35.
BN UI / bodyHind SiliguriDrawn for screen UI: open counters, simplified conjuncts that survive 13–15px on 720p. Ships 400/500. Bundled (subset) so BN never falls back to a fuzzy system face.
NumeralsRoboto tabularfont-variant-numeric: tabular-nums lining-nums on every financial figure so columns align.
BD numerals decision (override of the brief's implied requirement). Currency is always rendered in Western-Arabic digits (৳1,86,400), even in BN mode. Bengali digit glyphs (০-৯) aren't reliably tabular and slow reading at service speed. We translate words and labels to Bengali, not the money digits.

b · Two-weight rule

Only w400 (Regular) and w500 (Medium). No w600+. Two weights ship smaller, stay consistent, and avoid the sub-pixel smear heavier weights show on low-DPI in sunlight.

The one tension: numericHero (the single dominant money number) wants more punch than w500 gives in bright light. We compensate with size + near-black ink + tight tracking rather than adding a weight. This is the only place the two-weight rule is under strain — flagged, held.

e · Bilingual rules

  • Digits: currency & counts stay Western-Arabic in both languages (see flag above). Only prose translates.
  • ৳ symbol: always precedes the number with a hair-space (৳ 240), never a trailing "Tk". Part of the numeric token, inherits tabular metrics.
  • Grouping: South-Asian lakh/crore grouping — ৳1,86,400 not ৳186,400. Whole Taka in operational views; paisa (.50) only in formal financial reports.
  • Line-height: EN 1.35, BN 1.55. BN strings get the larger leading so conjuncts don't clip the line above.
  • BN minimum: Bengali never renders below 13px even where the EN token is 12/11.

  • Always include units: "14 min", "0.8 kg", "৳490 avg ticket", "3.2 turns/day" — never a bare number where a unit clarifies it.
  • Buttons are imperative verbs: Take payment, Print bill, Reorder, Close day. Verbs over nouns, always.
  • BN is hand-written, never machine-translated. Bengali strings are authored by a native writer in the casual register an owner actually speaks (আজকের আয়, not a stiff literal gloss). Every EN string has a reviewed BN pair before ship.
  • Numbers: whole Taka in operational UI (round to nearest ৳), two decimals only in financial reports. Percentages to whole numbers unless <1% (then one decimal).

# .git/hooks/pre-commit

12Migration checklist

Tokens first, then components, then onboarding, then any screen-specific fixes. Done in order, feature screens never get touched.

Edit these

  1. theme/tokens.dart — replace the palette with the base + signal + data-viz tokens and the six accent maps (ThemeExtension). Do this first; nothing else compiles against new names until it exists.
  2. theme/accent.dart — new: the six accent definitions + the resolver that reads the outlet's saved choice (default teal).
  3. widgets/Tf* — re-point each primitive at the new tokens per Section 10. Only TfButton + TfFab need the ink→white text flip; the rest are swaps.
  4. onboarding/accent_step.dart — new step + live preview (Section 9).
  5. settings/appearance.dart — "Change accent" entry.

Don't edit

✓ Feature screens (orders, menu, inventory, dashboards, reports) — as long as they only use Tf* primitives and token names, they inherit everything. Audit for stray hex/raw-Text first (Section 11); fix those, not the layouts.

Existing outlets without an accent

✓ Default to teal silently on first load post-migration. Do not interrupt an established owner with a colour prompt; surface it once as a dismissible tip in Settings.

→Summary

Biggest visual change

The fixed yellow-on-cream brand is gone. The base is now a neutral professional grey-white that never changes, and "the brand colour" becomes a per-outlet accent (default teal) confined to CTAs, FAB, selected states and soft tints. The app stops looking like one festive restaurant and starts looking like infrastructure that each owner tints as their own.

The trade-off to know

Restraint costs a little warmth. A Tier-1 owner who loved the all-yellow feel now gets neutral surfaces with a saffron accent — warm, but calmer. The system gains coherence and tier-range; it loses some of the cheerful, maximal personality the old palette had. That's the intended swap, but it's a real one.

First three to build

1 · tokens.dart — base + signals + data-viz + six accent maps. 2 · TfButton & TfFab — the ink→white flip is the only true behaviour change; get it right and the rest are swaps. 3 · Accent onboarding step + the resolver that defaults to teal — so new outlets exercise the system end-to-end.

On your constraints: all sound and held exactly — fixed base, no tier palettes, deltas always signal-coloured, accent never signals status, single-layer shadows / blur ≤ 8 / no BackdropFilter, WCAG AA body (AAA where stated). The four places I overrode or flagged: BN never below 13px (not 12), currency digits stay Western-Arabic even in BN (speed + tabular alignment), signal hues pushed into separate lanes so saffron/clay accents can't read as warning/urgent, and numericHero leans on size+ink rather than a third weight.
