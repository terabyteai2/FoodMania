============================  CRITICAL INVARIANT  ============================
NULL-SAFE DB ADDITIONS — applies to EVERY new column/field, now and forever:
- NO new REQUIRED input in the regular FOH flow. Do NOT add a customer-details
  form to dine-in/parcel/counter — that flow stays as simple as it is. New data
  is captured ONLY when it already flows through the existing workflow.
- Customer identity (cohort/LTV) comes ONLY from ONLINE channels — Facebook
  Messenger + website storefront (they already carry customer_name/mobile_number).
  FOH walk-ins contribute NOTHING to cohort metrics and must never be forced to.
- EVERY new column defaults NULL/unset = "not configured". When untouched, existing
  logic must behave EXACTLY as before (e.g. wastage NULL => regular stock math
  unchanged; daily-target NULL => Tower uses its own default; advanced analytics
  with no underlying data => return null and the UI HIDES the card, never zero-fill).
- This is mandatory for all future additions too. When in doubt, make it nullable
  and hide rather than fabricate.

WHAT THIS PROJECT IS
--------------------
Existing production app ("Quickbytes", domain quickbytes.buzz) is being
reconstructed phase-by-phase to match the QuickBytes POS spec in
  admin_app/TARGET_APP_SOURCE_OF_TRUTH/  (QuickBytes-BUILD-SPEC.md = behavior,
  QuickBytes-POS-MOBILE.md = design system, App_design/*.jsx = React prototype
  reference, flow_frames/*.png = wireframes).
Decision: KEEP Flutter (no rewrite). Reshape UI/screens/flows/roles to the spec;
preserve native thermal printing, SQLite offline sync, bKash/UddoktaPay, FCM.
Mobile-first phone surface. Bilingual EN + বাংলা. Currency ৳ (BDT), integer-ish.

STACK
-----
admin_app/ : Flutter/Dart (mobile+desktop+web). State = single ChangeNotifier
  `PosAppController` provided via `AppScope` (InheritedNotifier). Manual Navigator

  + WebSocket (cloud_realtime_service) + SyncService.

  JSONB (Postgres-only). Routers in backend/routers/, business logic in services/.

============================== Current  ROLES / AUTH  ==============================
3 roles: owner > manager > waiter (spec §1). Migrated from old manager/staff.
Frontend `AccountRole` (admin_app/lib/src/models/account_role.dart):
  isManager = owner||manager (THE elevated-privilege gate; many call sites rely on
  it), isOwner, isWaiter. PosAppController exposes isManager/isOwner/isWaiter +
  canManageSettings(owner) / canMessages(mgr+) / canManageStock(mgr+) +
  setAccountRoleDemo() (More demo switcher) + counterModeEnabled (+setter).
Backend (backend/routers/admin.py): OWNER/MANAGER/WAITER/STAFF consts +
  MANAGEMENT_ROLES=(owner,manager), FLOOR_ROLES=(waiter,staff). Tenant creators are
  created as OWNER; invites create WAITER. require_manager checks accept
  MANAGEMENT_ROLES. Other routers gate on role string: pos.py/inventory.py use
  `role not in ("owner","manager")`; platform.py role set {owner,manager,waiter}.
  One-time guarded migration: database.py `_ensure_role_migration` maps legacy
  manager->owner, staff->waiter (flag row 'role_model_v2_migrated' in system_configs).
Auth tokens (backend/auth.py): device token (Bearer, sub=outlet_id, optional
  account_id; 365d) for /outlets/* + /admin/*; platform token (8h) for /platform/*;
  signup token (15m) for phone OTP. Providers: password(bcrypt), Google OAuth,
  phone OTP (dev bypass 000000 when enabled).
