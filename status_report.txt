WHAT THIS PROJECT IS
--------------------
Existing production app ("Terafoods", domain quickbytes.buzz) is being
reconstructed phase-by-phase to match the QuickBytes POS spec in
  admin_app/TARGET_APP_SOURCE_OF_TRUTH/  (QuickBytes-BUILD-SPEC.md = behavior,
  QuickBytes-POS-MOBILE.md = design system, App_design/*.jsx = React prototype

preserve native thermal printing, SQLite offline sync, bKash/UddoktaPay, FCM.

==============================  ROLES / AUTH  ==============================
3 roles: owner > manager > waiter (spec §1). Migrated from old manager/staff.
Frontend `AccountRole` (admin_app/lib/src/models/account_role.dart):
  isManager = owner||manager (THE elevated-privilege gate; many call sites rely on
  it), isOwner, isWaiter. PosAppController exposes isManager/isOwner/isWaiter +
  canManageSettings(owner) / canMessages(mgr+) / canManageStock(mgr+) +
  setAccountRoleDemo() (More demo switcher) + counterModeEnabled (+setter).
Backend (backend/routers/admin.py): OWNER/MANAGER/WAITER/STAFF consts +
  MANAGEMENT_ROLES=(owner,manager), FLOOR_ROLES=(waiter,staff). Tenant creators are
  created as OWNER; invites create WAITER. require_manager checks accept
  MANAGEMENT_ROLES. Other routers gate on role string: pos.py/inventory.py use
  `role not in ("owner","manager")`; platform.py role set {owner,manager,waiter}.
  One-time guarded migration: database.py `_ensure_role_migration` maps legacy
  manager->owner, staff->waiter (flag row 'role_model_v2_migrated' in system_configs).
Auth tokens (backend/auth.py): device token (Bearer, sub=outlet_id, optional
  account_id; 365d) for /outlets/* + /admin/*; platform token (8h) for /platform/*;
  signup token (15m) for phone OTP. Providers: password(bcrypt), Google OAuth,
  phone OTP (dev bypass 000000 when enabled).
